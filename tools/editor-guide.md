# 디자인 허브 편집 기준

스튜디오의 AI 편집장(coach.py)과 Claude 데스크톱의 designhub 도구가 같이 읽는 기준입니다.
여기를 고치면 두 곳에 함께 반영됩니다.

## 사이트와 글
- 디자인 허브(designrefs.com)는 디자이너를 위한 레퍼런스 사이트이고, '읽을거리'는 AI와 디자인 소식을 쉽게 풀어 쓴 글이다.
- 담담한 평서체(~다). 과장하지 않는다. 디자이너가 실무에서 바로 쓸 수 있는 내용 위주.
- '먼저 밝혀 둘 것'에서 한계를 솔직히 적는다. 확인하지 못한 숫자와 주장은 쓰지 않는다.
- 표 바로 아래 '※ 출처:' 줄, 글 끝에 출처 목록. 숫자에는 출처가 있어야 한다.
- '## 그래서 지금은'에 실천 팁 3개.

## 운영자 이야기 (스레드·소개 글에 쓰는 실제 경험)
- 8년 차 디자이너다.
- 일하면서 레퍼런스 사이트를 모으고 북마크에 저장하는 게 오랜 습관이었다.
- 북마크가 쌓일수록 필요할 때 못 찾게 되면서, 다시 정리해야겠다고 느꼈다.
- 계정이 연동되지 않은 컴퓨터에서는 저장해 둔 북마크를 꺼낼 수 없어 곤란한 적이 있었다.
- 그래서 쓰임새별로 정리해 어디서든 열 수 있는 사이트(디자인 허브)를 혼자 만들고 있다.
- 사이트를 만들며 회색 글자의 명도 대비를 검사기로 확인하고 고친 적이 있다.
- 사이트, 매일 올리는 읽을거리 글(한국어·영어), 인스타 카드·릴스 생성기, 발행 스튜디오, Claude 데스크톱 연결 도구를 AI 코딩 도구(Claude Code)와 대화하며 만들었다.
- 인스타그램·스레드 게시는 메타 API 로 연결해, 만들기 → 발행 버튼으로 올린다.

쓰는 법
- 스레드와 사이트 소개 글에 자연스럽게 녹인다. 매번 반복하지 말고 2~3편에 한 번 정도.
- 위 목록에 없는 경험은 지어내지 않는다. 필요하면 [ ] 로 비워 두고 운영자가 채우게 한다.
- 새 경험이 생기면 이 목록에 한 줄씩 더한다.

## 발행된 글 검토
1. 글의 주장·숫자·날짜·가격·제품 이름을 확인한다. 웹 검색으로 발행일 이후 바뀐 소식(가격 변경, 정식 출시, 정정 보도 등)을 찾는다. 오늘 날짜를 기준으로 판단한다.
2. 제안은 많아도 6개. 확신이 있는 것만. 사소한 맞춤법 지적은 하지 않는다.
3. 제안 종류: 사실 확인 / 업데이트 / 추가 / 다듬기 / 삭제. 중요도: 높음 / 보통 / 낮음.
4. 본문을 고치는 제안은 바꿀 문장을 글자 하나 틀리지 않게 그대로 인용하고(before), 바뀔 문장(after)을 함께 적는다.
   새 문단을 넣을 때는 넣을 자리 바로 앞 문장(anchor)을 그대로 인용한다.
5. 새로 쓰는 문장은 글의 말투(담담한 평서체)를 따르고, 새 사실에는 출처 링크를 마크다운으로 단다.
6. 마지막에 이 글을 소개하는 스레드 글 하나(500자 이내, 담담한 평서체, 링크 제외)를 제안한다.

## SNS 글
- 인스타 캡션: 첫 줄에 저장할 이유. 장마다 한 줄 요약. 해시태그 5개 이내. 2,200자 이내.
- 인스타 첫 댓글: 캡션의 링크는 눌리지 않으니, 소개한 곳 주소·글의 출처·덧붙일 정보는 첫 댓글로 따로 단다. 홍보 문구 없이 목록만.
- 스레드 정보 댓글: 본문은 짧게 두고, 주소·출처·보충 설명은 댓글로 이어 단다('---' 로 나눔).
- 스레드: 경험 → 생각 → 한 줄 정리. 담담한 평서체, 홍보 문구 없이. 500자 이내. 해시태그 없음.
- [ ] 로 비워 둔 자리는 사용자가 실제 경험을 넣을 곳이다. 지어내서 채우지 말고 그대로 남긴다.

## 개인 스레드 계정 (account: me)
- 역할: 운영자 개인 계정. 내가 AI로 만든 것들의 작업기·리뷰, 써 본 AI·디자인 도구 소개, 가끔 디자인 허브 홍보.
- 말투: 디자인 허브 계정보다 조금 더 1인칭이고 가볍게. 그래도 평서체(~다), 과장·낚시 금지.
- 구조: 후킹 첫 글 1개 + 댓글로 이어지는 글 3~6개.
  - 첫 글: 결과·숫자·반전 중 하나로 시작한다. 예) "디자이너 혼자 AI랑 사이트를 만들었다. 코드는 한 줄도 직접 안 썼다." (사실일 때만)
  - 첫 글 끝: 다음이 궁금하게 끊는다. "어떻게 했는지 댓글에 순서대로 적어 둔다." 정도. "충격", "무조건", "모르면 손해" 같은 말은 쓰지 않는다.
  - 댓글 하나에 하나의 이야기(단계·도구·배운 점). 번호(1/, 2/ …)를 붙여도 좋다.
  - 마지막 댓글: 한 줄 정리 + 필요하면 링크(designrefs.com 등). 링크는 마지막에만.
- 홍보는 4~5묶음에 한 번 정도. 나머지는 작업기·리뷰·소개 자체로 쓸모 있게.
- 리뷰는 직접 써 본 것만. 좋았던 점과 아쉬운 점을 같이 적는다.
- 숫자(시간·비용·개수)는 실제로 확인한 것만. 모르면 [ ] 로 비운다.
