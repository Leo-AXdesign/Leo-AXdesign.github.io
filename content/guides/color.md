색을 고르는 일은 세 단계로 나뉩니다. 후보를 찾고, 실제 화면에 입혀 보고, 읽히는지 검사하는 것. 컬러 사이트도 이 순서대로 쓰면 헤매지 않습니다.

### 후보 찾기

아무 기준 없이 시작한다면 Coolors가 가장 빠릅니다. 스페이스바만 누르면 조합이 바뀌고, 마음에 드는 색은 고정해 둘 수 있습니다. 남들이 고른 조합을 보고 싶다면 Color Hunt, 색상 이론에 맞춰 조화로운 조합을 만들고 싶다면 Adobe Color를 쓰세요. 브랜드 색 하나가 정해져 있다면 Color Space에 넣어 보면 어울리는 조합이 한꺼번에 나옵니다.

### 화면에 입혀 보기

팔레트는 다섯 칸짜리 띠로 볼 때와 실제 화면에 칠했을 때 인상이 완전히 다릅니다. Realtime Colors와 Happy Hues는 고른 색을 웹 페이지 전체에 바로 입혀 줘서, 어떤 색이 배경이고 어떤 색이 버튼인지 감을 잡기 좋습니다.

UI 작업이라면 한 가지 색으로 밝기 단계를 만들어야 할 때가 많습니다. UI Colors는 색 하나로 50부터 950까지 단계를 만들어 주고, Radix Colors와 Material Theme Builder는 처음부터 단계가 설계된 체계를 줍니다.

### 읽히는지 검사하기

마지막 단계를 건너뛰는 경우가 많은데, 가장 중요합니다. 회색 글씨가 예뻐 보여도 배경과 대비가 부족하면 읽기 어렵습니다. WebAIM Contrast Checker에 글자색과 배경색을 넣어 WCAG 기준(본문은 4.5:1)을 넘는지 확인하세요. 공공기관 일이라면 이 기준을 지켜야 하는 경우가 많습니다.

인쇄물이라면 화면 색이 그대로 나오지 않는다는 것도 기억하세요. 팬톤 번호나 CMYK 값은 Pantone과 Encycolorpedia에서 찾을 수 있습니다.
