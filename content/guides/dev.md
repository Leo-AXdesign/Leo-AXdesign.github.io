디자인과 개발이 만나는 자리에서 쓰는 자료를 모았습니다. 디자이너가 코드를 다 알 필요는 없지만, 개발자가 무엇을 기준으로 구현하는지 알면 시안을 넘긴 뒤 오가는 질문이 크게 줄어듭니다.

### 디자인 시스템을 참고할 때

새로 디자인 시스템을 만든다면 처음부터 다 만들기보다 잘 만든 시스템을 먼저 읽어 보세요. 공공 프로젝트라면 KRDS를 따라야 하는 경우가 많고, 앱이라면 플랫폼 가이드인 Material Design 3와 Apple HIG가 기준이 됩니다. 문서를 어떻게 쓰는지 배우고 싶다면 Atlassian과 Shopify Polaris가 좋은 교과서입니다.

버튼이나 탭 같은 컴포넌트 하나를 두고 다른 회사들은 어떻게 했는지 비교하고 싶다면 Component Gallery가 가장 빠릅니다.

### 개발자와 같은 말을 쓰고 싶을 때

요즘 웹 서비스는 shadcn/ui와 Tailwind CSS로 만드는 경우가 많습니다. 개발 팀이 이걸 쓴다면 시안도 이 컴포넌트 구조에 맞춰 잡는 편이 구현이 빠르고 결과물도 시안과 가까워집니다. 컴포넌트를 어떻게 쪼갤지 고민된다면 Storybook으로 정리된 사례를 찾아보세요.

### 움직임을 정할 때

"부드럽게 움직이게 해 주세요"라고만 쓰면 사람마다 다르게 해석합니다. Easings.net이나 cubic-bezier.com에서 이징 곡선을 골라 값으로 넘기면 오해가 줄어듭니다. 화려한 인터랙션 아이디어는 Codrops와 CodePen에 많습니다.

### 넘기기 전에 확인할 것

색 대비와 글자 크기 같은 접근성 기준은 WCAG 2.2 Quick Reference에서, 특정 CSS 기능을 브라우저가 지원하는지는 Can I Use에서 확인할 수 있습니다. 반응형 화면은 Responsively로 여러 기기 크기를 한꺼번에 띄워 보면 빠뜨린 화면을 찾기 쉽습니다.
